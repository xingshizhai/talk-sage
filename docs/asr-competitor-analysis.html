01竞品 ASR 模型概览

共分析六款产品或参考项目，涵盖云端、离线批处理、流式三种部署形态。

02架构模式分类

竞品实现可归为三类架构，TalkSage 目前处于第一类（流式），精度天然低于后两类。

架构类型 代表产品 精度 延迟 说明
流式推理 TalkSage（Paraformer-zh） 中等 低 <300ms 每帧实时输出，无法回望后续音频修正错误
VAD 切段 + 离线批处理 Meetily、noScribe、WLK 高 中 1–3s VAD 切段后跑全上下文 Encoder-Decoder，Beam Search 充分
窗口重转写 whisper-flow 高 中 <1s 滑动窗口积累音频后整体重跑，随时间延迟劣化

03识别效果差距诊断

TalkSage 中文识别效果偏弱有五个相互叠加的原因，从最根本到可快速修复排列如下。

根因 1
流式架构的精度天花板
TalkSage 中文核心引擎是 Paraformer-zh（streaming）——流式模型每隔数百毫秒就必须输出结果，没有机会看到后续音频来修正当前帧的识别错误。竞品普遍使用的 Whisper / faster-whisper 是 Encoder-Decoder 离线架构：等整段音频结束（或 VAD 切段后）再推理，能利用完整语音上下文，Beam Search 也更充分。相同说话人、相同句子，Whisper large-v2 的 CER 通常比 Paraformer-zh streaming 低 5–15 个百分点。
根因 2
模型参数量：轻量档 vs 竞品主力档
引擎参数量产品
Paraformer-zh streaming（当前默认中文）~220MTalkSage
Whisper Base74MTalkSage 备用
Whisper Small / Qwen3-ASR244M / 0.6–1.7BTalkSage 可选
NVIDIA Parakeet-TDT~1.1BMeetily
faster-whisper large-v2~1.5BnoScribe
Voxtral 4B4BWhisperLiveKit
TalkSage 最大可用模型仍属小参数档；竞品主力引擎普遍是其 3–6 倍体量。
根因 3
CPU-only 推理限制了可用模型规模
sherpa-onnx 支持 GPU，但 TalkSage 目前走 CPU 路径。GPU 推理比 CPU 快 5–10 倍，让竞品能负担更大模型而不卡顿。当前在 CPU 上跑 WhisperSmall 的 RTF ≈ 0.8–1.2，勉强实时；large 系列在普通笔记本 CPU 上 RTF > 5，完全无法用于实时场景。Meetily 默认 Metal/CUDA，noScribe 默认 CUDA，Apple Silicon 上的 MLX Whisper RTF 可达 0.05 以下。
根因 4
VAD 切段工程精细度不足
Paraformer-zh 流式结果质量强依赖 VAD 切段粒度。sherpa-onnx 内置 VAD 在快速语速、长句、语速不均匀时切段不准确，导致模型拿到残缺音频帧产出错误。

竞品的对策： Meetily 使用 Silero VAD + 能量过滤 + redemption timer 三层 VAD 工程化调优；WLK 的 LocalAgreement 策略等多轮转写结果稳定后才提交 final；whisper-flow 以"文本连续 N 轮不变"为 final 信号，避免 VAD 漏判。
已修复
无标点输出 + 纯停顿断句
流式 Paraformer-zh 不输出标点，历史上断句完全依赖停顿——长句不停就不断，语义完全不切分。

已解决：本周新增 CT-Transformer 标点恢复模型（PunctuationRestorer），在 finish_speech() 中对 Paraformer 输出补标点后按 。！？ 做语义切句（split_on_strong_boundaries()），每个子句独立发出 DomainEvent::Segment，时间戳按字数比例分配。

04改善路径

立即
引导用户在会后开启 Whisper 模式。精度要求高的场景，会后用 WhisperSmall / Qwen3-ASR 离线转写，比实时流式精度高显著。界面上可在录音结束后自动触发离线重转写并替换字幕。
中期
在 Apple Silicon 上开启 Metal/CoreML 加速。sherpa-onnx 支持 CoreML backend，M 系芯片可将 WhisperSmall / Qwen3-ASR 加速 3–5×，RTF 降到 0.2 以下，届时可实时跑中型模型。
中期
实时路径切换为"VAD 切段 + 离线引擎"模式。仿 Meetily / WLK 思路：Silero VAD 切段后交给 Qwen3-ASR（离线）推理，延迟约 1–2s，精度大幅提升，同时保留标点恢复流程。
长期
评估接入 Parakeet-TDT 或 whisper-large-v3-turbo。NVIDIA Parakeet-TDT（~1.1B）是目前英文 ASR 开源最优解之一，fast-whisper large-v3-turbo 在精度与速度间取得良好平衡。中文方向可关注 SenseVoice-Large（阿里）的 ONNX 移植进展。
长期
AISHELL-1 基准进 CI。已有 bench_cer 工具 + download_aishell1_test.py 脚本，将 7176 条测试集 CER/RTF 作为每次发布的质量门禁，量化任何模型或参数变更的识别影响。

05结论

核心结论：TalkSage 识别效果偏弱的主要原因是流式架构的精度天花板加上 CPU 限制了可用模型规模，而非代码实现问题。竞品走的是"VAD 切段 → 离线大模型推理"路线，用稍高延迟换取显著更高的精度。

已完成的标点恢复与语义切句解决了最明显的断句问题。下一步最有价值的改进是：

  1. 短期：引导用户在会后使用更大的离线引擎重转写
  2. 中期：在 Apple Silicon 上启用硬件加速，实现实时路径上跑中型模型
  3. 长期：实时路径架构迁移为"VAD 切段 + 离线批处理"，向竞品对齐
