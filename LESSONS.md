# Lessons from merged work

talksage's code is written, reviewed, merged and released by agents. Each night
the day's commits are reviewed for what had to be fixed again, what shouldn't
have merged and what was verified too thinly. What we learned is kept here.
Read this before changing code. Each lesson is a rule, then why, then the
evidence. "Seen" counts the days a review found it. A lesson seen on 3 or
more separate days moves into [docs/code-standards.md](docs/code-standards.md).

The marker above is the last commit a night review has read. The next review
reads commits after it, and then advances the marker to the last commit it
read, with that commit's time. While the marker is `none`, review that day's
commits only. Do not mine older history, and do not copy lessons from another
project.

One finding, one entry:

**One sentence: the rule.** One more sentence if it needs a how.

- The reason, with the commit and the issue number.
- Seen 1× (YYYY-MM-DD).

The same lesson on a later day adds its evidence and its date to that entry.
It does not get a second entry. On the third separate day, move the rule and
its evidence into the code standards, and leave one line under
[Moved to the code standards](#moved-to-the-code-standards). A review still
checks it there.
